Application macOS native SwiftUI (macOS 13+) de sauvegarde incrémentale vers un disque externe, nommée **MY SIMPLE BACKUP** (même nom en français et en anglais ; anciennement « Sauvegarde Mac »). Les noms internes n'ont volontairement pas changé : cible/module `SauvegardeMac`, exécutable `SauvegardeMac`, bundle id `com.cepe.sauvegarde-mac` (le changer ferait perdre l'accès complet au disque, les réglages et l'historique). Une ancienne version Python/tkinter (rsync + py2app) a précédé cette application ; seule subsiste la reprise de sa destination enregistrée.

## Commandes

```bash
# Tests du moteur (macOS ou Linux ; Swift 5.9+). Sur macOS, compile aussi l'app.
swift test
swift test --filter SyncEngineTests/testEmptySourceDoesNotWipeDestination   # un seul test

# Build complet sur macOS : swift test + swift build + assemblage/signature → dist/MY SIMPLE BACKUP.app
bash build.sh [--install] [--open] [--debug] [--skip-tests]   # journaux dans build/
```

Pas de projet Xcode ni de XcodeGen : volontairement, tout passe par Swift Package Manager (Xcode 15.0 sur macOS 13 doit suffire ; XcodeGen n'y est plus installable via Homebrew). Ne pas réintroduire d'outil tiers ni de fonctionnalité exigeant Swift > 5.9 / Xcode > 15.0.

Sous Linux (sessions cloud), `Package.swift` n'expose que `BackupCore` (cible app sous `#if os(macOS)`) ; pour l'app, seul `swiftc -parse Sources/SauvegardeMac/*.swift` est possible, plus un `swiftc -emit-sil -wmo -module-name SauvegardeMac -o /dev/null` (et non `-typecheck`, qui ignore les erreurs d'initialisation comme « self used before all stored properties are initialized ») de `BackupController`/`BackupSource`/`SystemInfo` (avec `Sources/BackupCore/*.swift`) avec une toolchain **Swift 5.9** (celle d'Xcode 15.0) et de petites imitations d'AppKit/Combine. Swift 6 est plus permissif sur l'isolation d'acteur : par exemple `controller.dict[k] = v` dans `MainActor.run` passe en 6.0 mais échoue en 5.9 (« cannot be passed 'inout' to 'async' function call »), d'où des méthodes dédiées comme `setSize`. Toute modification de l'app est à faire valider par une compilation sur Mac.

## Architecture

- **`Sources/BackupCore/`** (Foundation uniquement) : `SyncEngine` (équivalent de `rsync -a --safe-links [--delete]`) `AppInventory` (liste des `.app` → `applications.txt`), et le modèle du journal `RunReport`/`SourceReport` avec `HistoryStore` (historique JSON). Tout code de copie/suppression doit rester dans ce module et être couvert par des tests (`Tests/BackupCoreTests/`) ; les appels Darwin spécifiques sont sous `#if canImport(Darwin)`.
- **`SyncEngine`** : deux phases — *plan* (parcours itératif de la source, sans récursion, + comparaison taille/date à `modifyWindow` = 2 s près, aucune écriture) puis *exécution* des actions. Dossiers listés par `SyncEngine.listDirectory` (`opendir`/`readdir`) et non `FileManager.contentsOfDirectory`, qui omet les fichiers « ._nom » sur macOS. Copie par blocs dans `.sauvegarde-XXXXXXXX.tmp` puis `rename` ; attributs étendus via `copyfile(COPYFILE_XATTR)` (volontairement ni ACL ni drapeaux, qui bloqueraient les sauvegardes suivantes). Garde-fous testés à préserver : refus si source et destination se recouvrent (y compris via lien symbolique, comparaison insensible à la casse), aucun lien de la destination suivi, dossier source illisible ⇒ aucune suppression correspondante, source vide ⇒ pas d'effacement de la destination, fichiers AppleDouble « ._nom » (exFAT/FAT) jamais supprimés tant que « nom » existe, destination disparue en cours de route ⇒ `SyncError.destinationUnavailable` (arrêt immédiat), bits setuid/setgid/sticky jamais copiés, permissions abandonnées pour la sauvegarde si le volume les ignore, `--safe-links`, remplacement d'un dossier par un fichier seulement si la suppression est activée.
- **`Sources/SauvegardeMac/`** (SwiftUI, cible exécutable) : `BackupController` (`@MainActor ObservableObject`) porte l'état ; la sauvegarde est orchestrée par une `Task.detached` ; le moteur (bloquant, parfois des heures) tourne sur un thread dédié (`onDedicatedThread`, pile de 8 Mo) pour ne pas occuper le pool de Swift. Elle met à jour le journal structuré `run: RunReport` (un `SourceReport` par élément : état, résumé, éléments non copiés) via des méthodes `@MainActor` dédiées (`beginSource`, `finishSource`…) et la progression via `Task { @MainActor … }` (`updateProgress` ignore les mises à jour tardives d'un autre élément) ; l'annulation passe par un `CancellationFlag` partagé. Pendant une sauvegarde, le bouton de fermeture de la fenêtre est désactivé (sa fermeture quitterait l'app) et ⌘Q passe par `AppDelegate.applicationShouldTerminate` → `shouldTerminate()` : confirmation, annulation, puis `.terminateLater` jusqu'à la fin propre. `JournalView` affiche ce journal (en-tête d'état, une ligne par élément, copie en texte via `RunReport.plainText`).
- **Historique** : à la fin de chaque sauvegarde (terminée ou annulée), `finishRun` l'ajoute via `HistoryStore.appending` puis l'écrit en arrière-plan (file série `historyQueue`, vidée par `flushHistory()` avant de quitter) dans `~/Library/Application Support/com.cepe.sauvegarde-mac/history.json` (100 sauvegardes max, 200 éléments non copiés max par élément, `issueCount` garde le total). Au lancement, le journal affiche la dernière sauvegarde de l'historique. `HistoryView` (feuille, ⌘Y ou bouton du journal) liste les sauvegardes (suppression unitaire : bouton du détail, touche ⌫ ou clic droit) et réutilise `JournalView(listHeight: nil)`. Éviter `DisclosureGroup` hors `List` sur macOS : il ne réagit qu'au clic sur le triangle (d'où le bouton maison de `SourceRow.issuesList`). Décodage Codable synthétisé : tout nouveau champ de `RunReport`/`SourceReport` doit être optionnel, sinon l'historique existant devient illisible ; il est alors mis de côté (`history.illisible-<horodatage>.json`, signalé à l'utilisateur) au lieu d'être écrasé. `ContentView` rafraîchit toutes les 4 s les pastilles d'accès et les apps ouvertes.
- **Sources** déclarées dans `BackupSource.all` : chaque dossier est copié dans `<destination>/<nom du dossier>/`, l'inventaire dans `<destination>/applications.txt`. Les apps surveillées le sont par identifiant de bundle (`NSRunningApplication`).
- **Destination** mémorisée dans `UserDefaults` (`destinationPath`), conservée même si le disque n'est pas branché (`destinationAvailable`, affiché « Disque non connecté ») ; sélection des éléments mémorisée (`selectedSources`), pas l'option de suppression (volontairement) ; au premier lancement, reprise de `~/Library/Preferences/com.cepe.sauvegarde-mac.json` écrit par l'ancienne version.
- **Bundle** : `build.sh` copie l'exécutable SwiftPM dans `dist/MY SIMPLE BACKUP.app/Contents/MacOS/SauvegardeMac` avec `Bundle/Info.plist` (bundle id, version, textes de permission : à modifier là), ainsi que `Bundle/AppIcon.icns` dans `Contents/Resources/`, puis signe avec runtime renforcé (`codesign --options runtime`) : identité `SIGN_IDENTITY`, sinon premier certificat Developer ID / Apple Development du trousseau, sinon ad hoc.

- **Icône** : source `Bundle/AppIcon.svg` (grille macOS : carré arrondi de 824 px dans 1024). Après modification, régénérer `AppIcon.icns` et l'aperçu `AppIcon.png` avec `node Bundle/make_icon.mjs` (rendu Chromium via Playwright, assemblage .icns en PNG) et versionner les deux ; `build.sh` ne fait que copier le .icns.

- **Langues (FR/EN)** : tout texte affiché passe par `tr("français", "english")` (`Sources/BackupCore/Localization.swift`), y compris les messages du moteur ; pas de `Text("…")` littéral (sauf le nom de l'app). Nombres, tailles, durées et dates via `L10n.number/count/bytes/duration/dateTime` (jamais `.formatted()` ni `ByteCountFormatter`, qui suivraient la langue du système). `L10n.language` (verrouillé, lu aussi par le thread de sauvegarde) est piloté par `BackupController.language` (`UserDefaults` `appLanguage`, par défaut la langue du système ; écrit aussi `AppleLanguages` pour les menus macOS, effectifs au prochain lancement). `ContentView` porte `.id(controller.language)` pour tout retraduire ; le sélecteur (drapeaux `AppLanguage.flag`) est en haut de la fenêtre, au-dessus de Destination. L'historique enregistre des compteurs (`sourceFiles`, `deletedItems`… optionnels) et `SourceReport.displaySummary` recompose le résumé dans la langue courante ; le nom des éléments vient de `BackupSource.label(for:)`. `Bundle/{fr,en}.lproj/InfoPlist.strings` (textes des autorisations) et `CFBundleLocalizations` sont copiés par `build.sh`.

- **Sauvegarde iCloud (en cours, étape 1/4 : briques de base)** : `EncryptedArchive` (`#if canImport(AppleArchive)`) écrit une archive Apple Archive compressée LZFSE et chiffrée par mot de passe (AEA, profil `hkdf_sha256_aesctr_hmac__scrypt__none`) au fil de l'eau, via un tube (`pipe`, `F_SETNOSIGPIPE`) lu par un thread qui découpe le flux chiffré en morceaux `archive.aea.0001…` ; `beforeNewPart` peut bloquer (contre-pression : limite l'espace local). `extract` recolle les morceaux dans l'ordre (`beforeReadingPart` pour les télécharger). Fermetures de flux explicites et dans l'ordre (une erreur finale ne doit pas être avalée). `ICloudDrive` (`#if os(macOS)`) : état d'envoi (`ubiquitousItemIsUploaded…`), attente, `evictUbiquitousItem` (libère la copie locale), `startDownloadingUbiquitousItem`. Pas d'API publique pour forcer l'envoi : on attend puis on libère. Tests `EncryptedArchiveTests` (Mac uniquement) ; diagnostic réel : `swift run -c release icloud-probe "<dossier de test iCloud>"`. Plan validé : une chaîne par dossier (archive complète puis incréments, jamais de nouvelle complète automatique ; bouton manuel « Repartir d'une archive complète »), inventaire chiffré envoyé aussi, `applications.txt` en clair, mot de passe dans le trousseau local, sous-dossier iCloud choisi, « Terminée » seulement une fois tout envoyé, restauration à une date choisie vers un dossier vide, partie iCloud possible sans disque externe.

## Contraintes macOS

- App **hors sandbox** (lecture de tout le dossier utilisateur) : distribution Developer ID, pas Mac App Store. Bundle id `com.cepe.sauvegarde-mac`. Pas d'entitlements (aucune capacité requise hors sandbox).
- **Full Disk Access** nécessaire pour la photothèque et les bibliothèques Musique/iMovie. `SystemInfo.hasFullDiskAccess` le détecte en ouvrant la base TCC de l'utilisateur. macOS rattache cet accès à la signature : en signature ad hoc (sans certificat dans le trousseau), il faut le redonner après chaque build.
